# Phase 4 — 엣지 경량화 & 해상도 스펙트럼 실험

> 목표: 실제 엣지 단말기 제약을 가정해, 모델 크기·입력 해상도를 바꿀 때
> 성능·속도·조건별 영향(특히 야간)이 어떻게 변하는지 정량 측정.
> 배경: 최고 성능 모델(E3-4)의 속도가 이미 실시간을 크게 초과(105 FPS)함을 확인
> → 초점을 "속도 향상"이 아니라 "해상도·모델 크기에 따른 성능·조건별 trade-off 분석"으로 재설정.

## 1. 사전 발견 — 속도는 병목이 아니다

- E3-4(YOLOv8s/640) e2e **105 FPS**, 추론 VRAM 78MB.
- 병목은 모델 추론이 아니라 전처리+후처리(순수 추론 197 FPS vs e2e 105 FPS).
- → 모델·해상도 축소로는 e2e 속도가 크게 개선되지 않음. 경량화 이득은 VRAM·모델 크기에 있음.

## 2. 실험 구성

| 실험 | 모델 | 학습 해상도 | 추론 해상도 | 목적 |
|------|------|-------------|-------------|------|
| E4-1 (=E3-4) | s | 640 | 640 | 기준 |
| E4-2 | s | 640 | 416 | 해상도 축소(추론만) |
| E4-3 | n | 640 | 640 | 모델 축소 |
| E4-4 | n | 640 | 416 | 둘 다(엣지 극단) |
| E4-5 | s | **416** | 416 | 학습-추론 해상도 일치 검증 |
| E4-6 | s | 640 | **736** | 해상도 상향(실기기 상한) |

## 3. 핵심 결과

| 실험 | mAP50-95 | 주간 | 야간 | gap(50-95) | e2e FPS | VRAM |
|------|----------|------|------|------------|---------|------|
| E4-4 (n/416) | 0.174 | 0.173 | 0.179 | -0.006 | 135 | 20 MB |
| E4-2 (s/640→416) | 0.222 | 0.222 | 0.228 | -0.006 | 125 | 58 MB |
| E4-5 (s/416→416) | 0.225 | 0.226 | 0.221 | +0.001 | ~125 | ~58 MB |
| E4-3 (n/640) | 0.243 | 0.246 | 0.237 | +0.008 | 125 | 32 MB |
| E4-1 (s/640) | 0.292 | 0.297 | 0.286 | +0.011 | 105 | 78 MB |
| **E4-6 (s/736)** | **0.305** | 0.311 | 0.292 | +0.019 | 117 | 90 MB |

## 4. 발견

### 발견 1 — 정확도는 해상도에 비례해 상승 (416 < 640 < 736)
- 416: 0.222 → 640: 0.292 → 736: **0.305**. 해상도를 올릴수록 계속 상승.
- 736은 640 학습 모델을 **추론만** 736으로 한 것인데도 최고 성능 → 해상도 상향의 이득이 재학습 없이도 발현.
- 본 프로젝트 난제(원거리 소형 객체)와 직결: 해상도가 높을수록 작은 객체가 살아남.

### 발견 2 — 해상도 축소가 모델 축소보다 정확도에 더 치명적
- 모델만 축소(s→n, 640): 0.292 → 0.243 (-0.049)
- 해상도만 축소(640→416, s): 0.292 → 0.222 (-0.070)
- **엣지 배포 시사점:** 정확도 우선이면 해상도보다 모델 크기를 먼저 줄이는 것이 유리.

### 발견 3 — 저해상도의 gap 역전은 "학습-추론 불일치 아티팩트"였다
- E4-2(640학습→416추론): gap -0.006 (야간>주간, 역전)
- E4-5(416학습→416추론): gap +0.001 (주간>야간, 정상 복귀)
- **해석:** 640 학습 모델을 416으로 추론하면 주간(디테일 多)이 특히 손해 → 야간이 상대적으로 높아 보였음. 416으로 제대로 학습하니 주간이 회복(0.222→0.226)되어 역전 소멸.
- **교훈:** 반직관적 결과(저해상도서 야간 유리)를 추가 실험으로 검증해 원인 규명. 단일 실험만 보고 단정했다면 틀린 결론이었을 것.
- 부수 발견: 640학습→416추론(0.222) vs 416학습→416추론(0.225) 차이가 +0.003에 불과 → YOLO는 학습-추론 해상도 불일치에 비교적 강건. 실무상 매 해상도 재학습 불필요.

### 발견 4 — 속도는 병목 때문에 거의 불변, VRAM만 크게 변동
- 전 해상도·모델에서 e2e 105~135 FPS (데스크톱 GPU 기준 모두 실시간 초과).
- VRAM: 736 90MB ~ n/416 20MB. 메모리 제약 엣지엔 경량화가 유효.

## 5. 실무 연결 — "정확도는 해상도에 비례, 실기기 속도가 상한을 결정"

- 본 실험(데스크톱 3060 Ti): 736도 117 FPS로 여유 → 정확도 최고인 736 채택 가능.
- 그러나 실제 엣지 단말기: 736이 실시간 마지노선(현장 확인).
- **통합 결론:** 해상도↑ → 정확도↑ 는 계속 성립하나, **실기기의 속도 한계가 사용 가능한 해상도 상한을 결정**한다. 소형 객체를 살리려 해상도를 올리고 싶어도(예: 1920), 실기기가 736까지만 감당하면 거기서 타협해야 함.

## 6. 프로젝트 관통 통찰 — "제약의 종류가 희생 조건을 결정한다"

| 제약 종류 | 희생 조건 | 이유 |
|-----------|-----------|------|
| 백본 동결 (Phase 2) | 야간 (gap 확대) | 야간 특화 지식 재학습 차단 |
| 해상도 축소+불일치 (Phase 4) | 주간 (gap 역전) | 디테일 많은 주간이 더 손해 (단, 재학습 시 소멸) |

- 표면적으로 상반돼 보이나 본질 동일: 제약을 걸면 특정 조건이 먼저 희생되며, 어느 조건인지는 제약의 성격에 달림.
- 전체 평균 mAP만 봐서는 드러나지 않는, 조건별 분리 평가로만 발견 가능.

## 7. 결론
- **최고 정확도 = E4-6(s/736)**, 데스크톱에선 실시간 여유.
- **엣지 상한 해상도 = 736** (실기기 속도 마지노선).
- **극저메모리 타겟 = E4-4(n/416)**, 정확도 손실 크나 VRAM 20MB.
- 다음(Phase 5): 양자화·TensorRT로 배포 형식 경험 및 엣지 최적화.

## 8. 방법론 메모
- 해상도 변경은 재학습 불필요(YOLO는 fully-convolutional, 입력 크기 무관). 32의 배수 권장(416·640·736 모두 해당).
- 속도 측정: warmup 50 + synchronize + p50/p95/p99, batch=1, 측정 전 nvidia-smi로 GPU 점유 확인(타 작업 시 20~50 FPS 저하 확인됨).
- 정확도(mAP)는 GPU 부하 무관(결정적), 속도(FPS)는 민감.

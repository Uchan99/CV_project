# Phase 4 — 엣지 경량화 실험 (모델 크기 · 해상도)

> 목표: 실제 엣지 단말기 제약(YOLOv8n, 416px)을 가정해, 모델·해상도를 줄일 때
> 성능·속도·조건별 영향(특히 야간)이 어떻게 변하는지 측정.
> 배경: Phase 4 시작 시 속도 벤치마크 결과, 현재 모델이 이미 실시간 요구를 크게 초과(105 FPS)함을 확인.
> → 초점을 "속도 향상"이 아니라 "엣지 제약 하 성능 손실 및 조건별 영향 분석"으로 재설정.

## 1. 사전 발견 — 속도는 병목이 아니었다

최고 성능 모델(E3-4, YOLOv8s/640)의 속도 측정 결과:
- e2e **105 FPS** (30 FPS 기준의 3.5배), 추론 VRAM 78MB.
- **병목은 모델 추론이 아니라 전처리+후처리**: 순수 추론 197 FPS vs e2e 105 FPS.
- 시사점: 모델·해상도를 줄여도 e2e 속도는 크게 개선되지 않음. 경량화의 이득은 속도보다 VRAM·모델 크기에 있음.

## 2. 실험 구성 (2×2)

| 실험 | 모델 | 해상도 | 비고 |
|------|------|--------|------|
| E4-1 (=E3-4) | YOLOv8s | 640 | 기준 (최고 성능) |
| E4-2 | YOLOv8s | 416 | 해상도만 축소 (평가만) |
| E4-3 | YOLOv8n | 640 | 모델만 축소 (n 재학습) |
| E4-4 | YOLOv8n | 416 | 둘 다 (실제 엣지 타겟) |

- E4-3/E4-4용 YOLOv8n은 E3-4와 동일한 데이터 전략(야간 오버샘플링+증강)으로 재학습 → 공정 비교.

## 3. 핵심 결과

| 실험 | mAP50-95 | 주간 | 야간 | gap(50-95) | e2e FPS | 추론 VRAM |
|------|----------|------|------|------------|---------|-----------|
| E4-1 (s/640) | 0.292 | 0.297 | 0.286 | **+0.011** | 105 | 78 MB |
| E4-2 (s/416) | 0.222 | 0.222 | 0.228 | **−0.006** | 125 | 58 MB |
| E4-3 (n/640) | 0.243 | 0.246 | 0.237 | +0.008 | 125 | 32 MB |
| E4-4 (n/416) | 0.174 | 0.173 | 0.179 | **−0.006** | 135 | 20 MB |

## 4. 발견

### 발견 1 — 해상도 축소가 모델 축소보다 정확도에 더 치명적
- 모델만 축소(s→n): 0.292 → 0.243 (−0.049)
- 해상도만 축소(640→416): 0.292 → 0.222 (−0.070)
- **해상도 축소의 손실이 더 큼.** 본 프로젝트의 핵심 난제(원거리 소형 객체)와 직결 — 해상도를 낮추면 작은 객체가 소실되어, 파라미터 감소보다 타격이 큼.
- **엣지 배포 시사점:** 정확도 우선이면 해상도보다 모델 크기를 먼저 줄이는 것이 유리.

### 발견 2 — 저해상도(416)에서 day-night gap이 일관되게 역전
- 416px인 두 실험(E4-2, E4-4) 모두 gap 음수(−0.006) = **야간이 주간보다 높음**.
- 640px에서는 gap 양수(야간이 낮음)였으나, 416px에서 역전.
- **원인:** 해상도를 낮추면 주간이 더 크게 손해. 주간은 세밀한 디테일(원거리 차·표지판)이 많아 잃을 것이 많고, 야간은 원래 밝은 덩어리(헤드라이트·큰 차) 위주라 잃을 디테일이 적음.
- **모델 크기와 무관하게(s/n 공통) 해상도 416에서 재현** → 우연이 아닌 구조적 현상.

### 발견 3 — 속도는 병목(전후처리) 때문에 크게 안 변함, 단 VRAM은 크게 감소
- FPS: 105(s/640) → 135(n/416), 최대 축소에도 +28%에 그침.
- VRAM: 78MB → 20MB (약 74% 감소).
- **시사점:** 이 GPU에선 경량화가 속도보다 메모리 절감에 기여. 메모리가 극도로 제한된 엣지 장비엔 n/416이 유효.

## 5. 프로젝트 관통 통찰 — "제약의 종류가 희생되는 조건을 결정한다"

Phase 2와 Phase 4를 종합하면 일관된 원리가 도출됨:

| 제약 종류 | 희생되는 조건 | 이유 |
|-----------|---------------|------|
| 백본 동결 (Phase 2) | **야간** (gap 확대) | 야간 특화 지식을 재학습 못 함 |
| 해상도 축소 (Phase 4) | **주간** (gap 역전) | 디테일 많은 주간이 더 손해 |

- 표면적으로 상반돼 보이나, 본질은 동일: **"제약을 걸면 특정 조건이 먼저 희생되며, 어느 조건인지는 제약의 성격에 따라 다르다."**
- 전체 평균 mAP만 봐서는 절대 드러나지 않는, 조건별 분리 평가로만 발견 가능한 통찰.

## 6. 결론
- **최고 성능 유지 모델 = E4-1(s/640).** 속도가 이미 충분하므로 성능 우선 시 축소 불필요.
- **극저메모리 엣지 타겟 = E4-4(n/416).** 정확도 손실(0.292→0.174)은 크나 VRAM 20MB로 최소.
- 다음(Phase 5): 양자화·TensorRT로 배포 형식 경험 및 추가 최적화.

## 7. 방법론 메모
- 속도 측정: warmup 50 + torch.cuda.synchronize() + p50/p95/p99, batch=1. 측정 중 타 GPU 작업 배제 필수(1차 측정이 GPU 점유로 20~50 FPS 저하됨을 확인).
- 정확도(mAP)는 GPU 부하와 무관(결정적), 속도(FPS)는 부하에 민감 → 속도 측정 전 nvidia-smi 확인.
